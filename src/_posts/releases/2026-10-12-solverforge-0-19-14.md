**solverforge 0.19.14** is published on crates.io and released on GitHub
(2026-10-12), following `solverforge 0.19.13`. `cargo add solverforge` installs
0.19.14 and docs.rs serves the 0.19.14 API. The Rust `1.95` floor is unchanged.

## What Changed

### Dense existence updates avoid repeated growth checks

The count-backed existence engine introduced in 0.19.13 remains in place.
`DenseKeys::add` and `take` now check the count-table length before growing it
and update the touched-key list inline. Each key enters that list at most once
per event. Counts, alive/dead transitions, and semi/anti membership semantics
remain unchanged; this does not add a modeling API or establish a benchmark gain.

The inherited 0.19.13 engine answers pure-key existence from per-key occurrence
counts, restores complements through retained keys, and publishes incremental
notifications into caller-owned buffers. Residual predicates still use the
pair-backed `JoinerExistenceNode`.

### Every later join uses borrowed-row keys

The tagged API documentation now states the key-shape rule on cross `Bi`,
`Tri`, `Quad`, `Penta`, and arity-free `Chain` continuations. The first unary
relationship can use `equal_bi` with entity references. Every second or later
relationship uses `equal_on`: its left closure receives the complete prior
borrowed row, and its right closure receives a `Leaf` view of the new entity.

Passing entity-key closures to a later join does not typecheck. Access entities
through `row.left` / `row.right` and `.entity`, so the condition identifies the
intended binding even when the same entity type occurs more than once. Each
relationship still has its own key type; this release documents that existing
contract rather than changing it.

## Upgrade Checklist

- Update direct Rust dependencies deliberately and validate `Cargo.lock` against
  core `0.19.14`.
- Check every later join's closures against its borrowed row and right `Leaf`
  view; use `equal_on` rather than unary entity-key `equal_bi` closures.
- Retain incremental/full-score checks for existence threshold crossings and
  complemented streams when maintaining custom operator plans.
- Preserve separately released CLI, Python, app, and benchmark version boundaries.
